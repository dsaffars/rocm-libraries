```markdown
JIRA ID : AIHPBLAS-4893

## Motivation

geko's matrix-instruction designer proposes every matrix tile its tiling rules allow. A matrix instruction is the hardware matrix operation plus the tile shape around it. For many of those tiles, TensileLite, the kernel code generator, cannot emit a kernel: the tile needs more registers or more local data-store memory than the chip allows, for every parameter setting geko's generic search can sample. A generic search is the wide automatic search, as opposed to the older short heuristic list. Those samples still take time, and they never produce a kernel.

The author reports that about 40% of candidate tiles fail this way on one architecture, and about 28% on the other. The worst data type they cite fails for about 61% of its tiles.

## Technical Details

This change adds three pieces. None of them run unless the tuner opts in.

- `BUILDABLE_MIS` defaults to false. False keeps today's enumeration. True makes the designer read a precomputed list of tiles for which code generation succeeded at least once inside the generic search ranges. Set it in the config, with `BUILDABLE_MIS=1` in the environment, or in a `--list` file. If the environment is set, it replaces the config and the `--list` value. If the flag is on and the list file is missing, geko warns, prints the generation command, and enumerates every tile.
- Lists live in `geko/config_generator/mi_lists/<compiler target>/<GEMM name>.txt`. A five-integer line ending in a colon is M, N, K, B, and MIBlockM. Each following four-integer line is waveTileM, waveTileN, waveM, and waveN, and the loader appends it to that prefix, which restores the nine-integer tile. Identical lists in one directory are a `same_as <name>` line. Rejected tiles are not in the file. DepthU, how many K elements one loop iteration consumes, is recorded only in the optional CSV report, so a tuning run can still sample a DepthU that failed at generation time. One list is shared by generic and heuristic search, and by runs with StreamK off or on. StreamK is the persistent mode that keeps a kernel alive across tiles. The lists were generated with StreamK off. Subtile kernels, the separate kernel shape used for some block-scaled types, are not listed and are not filtered.
- `scripts/generate_buildable_mis.py` rebuilds the lists on the CPU. It does not use a GPU. For each candidate tile it tries fixed low-resource settings, then a grid over the parameters that dominate register and local-memory use, then one-parameter edits from the closest failures. The grid uses only the two smallest legal DepthU values. Other DepthU values are visited by the one-parameter stage, or only after the tile has already built. The script skips GEMM types that geko tunes only as subtile kernels.

The lists need to be rebuilt when TensileLite's code generator changes, or when geko changes which tiles it proposes. An old list drops a newly added tile. The installed geko package includes the text files. On this branch they are 374,446 bytes.
```
